# Phase 1: Terraform foundation and HCP workspace

## Goal

Create the `infra/` root module skeleton: pinned Terraform and provider versions, the HCP Terraform `cloud` block, provider configuration and input variables. Also create the HCP workspace, so `terraform init` and `validate` succeed locally and remotely.

## Context

- Versions checked on 2026-10-24:
  - Terraform `1.17.0` and `hashicorp/setup-terraform@v4`.
  - Providers: `vercel/vercel` 5.24.1, `supabase/supabase` 1.11.0, `integrations/github` 6.13.0 and `hashicorp/random` 3.9.1.
- Terraform is not installed locally. The user manages tools with `mise`.
- The workspace uses **remote execution**. The human-held credentials live only as sensitive HCP workspace variables, and GitHub Actions needs only `TF_API_TOKEN`.
- `*.auto.tfvars` files inside the uploaded configuration directory are loaded by remote runs. Non-secret values are committed there.

## Files to Create / Modify

- Create: `/home/namnn/src/itcnh1316/infra/versions.tf`: the `terraform { required_version = "~> 1.17.0" }` block, the `cloud { organization, workspaces { name = "classmate-directory-production" } }` block, and `required_providers` with `~>` minor pins.
- Create: `/home/namnn/src/itcnh1316/infra/providers.tf`:
  - `provider "vercel" { api_token = var.vercel_api_token, team = var.vercel_team_id }`
  - `provider "supabase" { access_token = var.supabase_access_token }`
  - `provider "github" { owner = var.github_owner, token = var.github_token }`
- Create: `/home/namnn/src/itcnh1316/infra/variables.tf`: every input, with a description, a type, `sensitive = true` on credentials, and `validation` blocks wherever `src/lib/env.ts` has a rule.
- Create: `/home/namnn/src/itcnh1316/infra/production.auto.tfvars`: non-secret values only.
- Create: `/home/namnn/src/itcnh1316/infra/.terraform.lock.hcl`: generated by `terraform providers lock -platform=linux_amd64`.
- Modify: `/home/namnn/src/itcnh1316/.gitignore`: add `.terraform/`, `*.tfstate`, `*.tfstate.*`, `crash.log`, and `*.tfplan`. Keep `.terraform.lock.hcl` tracked.

- [ ] In HCP Terraform, create the organization (or reuse one) and a CLI-driven workspace `classmate-directory-production`:

## Verification

- `terraform -chdir=infra fmt -check -recursive` exits 0.
- `terraform -chdir=infra validate` prints `Success! The configuration is valid.`
- `terraform -chdir=infra plan` runs remotely in HCP and reports `No changes` (there are no resources yet). This proves the workspace, the variables and the provider authentication.
- `git check-ignore infra/.terraform` matches. `git check-ignore infra/.terraform.lock.hcl` does not.
- `grep -rnE 'sb_secret_|eyJhbGciOi|scrypt:' infra/` finds nothing.

## Risks

- **Organization slug committed in `versions.tf`.** The slug is not a secret, but a fork would point at it. Forks have no token, so their runs fail closed.
- **Provider major upgrades.** The `~>` minor pins and the committed lock file keep upgrades deliberate.
